# ADR 0041: Ratchet `missing_docs` Exemptions and Document Core API Entrypoints

## Status
Accepted (extends [ADR 0005](0005-active-documentation-standard.md), [ADR 0013](0013-workspace-doc-lints-and-path-scoping.md), and [ADR 0036](0036-harden-ast-and-doctest-policy-audits.md))

## Context
1. **Unratcheted Item-Level `#[allow(missing_docs)]` Exemptions**: Workspace lints set `missing_docs = "warn"` in root [`Cargo.toml`](../../Cargo.toml), while hundreds of item-level `#[allow(missing_docs)]` attributes and crate-level `#![allow(missing_docs)]` directives accumulated across workspace crates and test/example targets without a downward ratchet in `unified_verification`. Core foundation and domain crates (`diagnostics`, `verified_engine`, `verified_engine_macros`, `federated_registry`, `domain_climate`) carried blanket item-level suppressions and zero or minimal `src/` `rustdoc` examples, leaving proc-macro and allocator invariants opaque in IDE hover tooltips.
2. **Legacy Architectural Heading Allowlist**: [`crates/unified_verification/src/doc_audit.rs`](../../crates/unified_verification/src/doc_audit.rs) and [`verification_whitelist.toml`](../../verification_whitelist.toml) exempted four first-party crates (`crates/diagnostics`, `apps/xtask`, `math_explorer`, and `math_explorer_gui`) from the mandatory `## 1. Overview & Architecture` and `## 2. Developer Instructions` README structure alongside vendored `egui_plot`.
3. **Mis-scoped Module Comment in `bcs.rs` and Sparse Domain `src/` Doctests**: [`crates/domain_physics/src/physics/solid_state/bcs.rs`](../../crates/domain_physics/src/physics/solid_state/bcs.rs) opened with outer `///` comments attached to a private `use` import instead of inner `//!` module documentation while carrying 17 `#[allow(missing_docs)]` attributes, and `domain_climate` and `domain_epidemiology` concentrated runnable examples in `README.md` rather than item-level `src/` docstrings.

## Decision
1. **AST `missing_docs` Policy Audit & Downward Ratchet**:
   - Extend `VerificationWhitelist` in [`crates/unified_verification/src/whitelist.rs`](../../crates/unified_verification/src/whitelist.rs) with `MissingDocsConfig` (`#[serde(deny_unknown_fields)]`), validating explicit `vendored_crates` and strictly positive (`>= 1`) per-file caps in `[missing_docs.files]` inside [`verification_whitelist.toml`](../../verification_whitelist.toml).
   - Add [`crates/unified_verification/src/policy_audit/missing_docs.rs`](../../crates/unified_verification/src/policy_audit/missing_docs.rs) and helper predicates in [`crates/unified_verification/src/policy_audit/lint_policy.rs`](../../crates/unified_verification/src/policy_audit/lint_policy.rs) to:
     - Ban inner `#![allow(missing_docs)]` and `#![expect(missing_docs)]` (including `rust::missing_docs` and nested `cfg_attr`) across all first-party crates while permitting vendored `egui_plot` only via `missing_docs.vendored_crates`.
     - Count outer `#[allow(missing_docs)]` and `#[expect(missing_docs)]` attributes across AST nodes and `macro_rules!` token streams, failing `test-policy-audit` whenever a file exceeds its cap, contains fewer attributes than its recorded cap (enforcing monotonic downward ratcheting), or is deleted without removing its `[missing_docs.files]` entry.
2. **Retire First-Party README Legacy Allowlist**:
   - Standardize [`math_explorer/README.md`](../../math_explorer/README.md), [`crates/diagnostics/README.md`](../../crates/diagnostics/README.md), [`math_explorer_gui/README.md`](../../math_explorer_gui/README.md), [`apps/xtask/README.md`](../../apps/xtask/README.md), and [`crates/unified_verification/README.md`](../../crates/unified_verification/README.md) with `## 1. Overview & Architecture` and `## 2. Developer Instructions`, shrinking `DEFAULT_LEGACY_ALLOWLIST` and `[doc_verification].allowlist` exclusively to vendored `egui_plot`.
3. **Core API & Domain `rustdoc` Coverage**:
   - Eliminate all `missing_docs` suppressions and add runnable `rustdoc` examples (`>= 3` per crate covering primary APIs and verification/error invariants) in `crates/diagnostics`, `crates/verified_engine`, `crates/verified_engine_macros`, `crates/federated_registry`, `crates/domain_climate`, and [`crates/domain_physics/src/physics/solid_state/bcs.rs`](../../crates/domain_physics/src/physics/solid_state/bcs.rs) (converting its top-of-file `///` comment to `//!`), plus item-level `src/` doctests in `crates/domain_epidemiology`.
   - Replace `#![allow(missing_docs)]` headers across first-party `tests/`, `examples/`, and `benches/` targets with concise `//!` crate-level doc comments.

## Consequences
- **Positive**: `test-policy-audit` and `check-docs` mechanically prevent new `missing_docs` exemptions, enforce downward ratcheting whenever grandfathered files are documented, require standardized README sections on all 19 first-party crates, and provide executable `rustdoc` examples across core verification, diagnostics, registry, climate, epidemiology, and BCS superconductivity APIs.
- **Neutral**: Public signatures in [`crates/unified_verification/api_baseline.json`](../../crates/unified_verification/api_baseline.json) and runtime behavior in `VerifiedAllocator` remain completely unchanged; remaining deep internal `#[allow(missing_docs)]` attributes in grandfathered modules are capped at their exact per-file counts in `verification_whitelist.toml`.
