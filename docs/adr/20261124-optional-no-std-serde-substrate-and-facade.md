# ADR: Optional `#![no_std]` Serde Across Substrate, Plot Outputs, and Facade

## Status
Accepted (complements [ADR 0022](0022-unify-preset-state-serialization.md) and [ADR 0036](0036-delete-simulation-model-traits-and-physics-adapters.md))

## Context
Embedded `#![no_std]` integrators, interactive plotting consumers, and headless `math_explorer` callers needed opt-in serialization across foundational numeric primitives, solver configurations, and plot diagnostics without inflating default binary sizes or destabilizing existing GUI presets:
1. **Workspace `serde` Default Features**: [`Cargo.toml`](../../Cargo.toml) previously enabled default `std` features on `serde`, preventing `#![no_std]` substrate and engine crates from deriving `Serialize` and `Deserialize` without pulling `std`.
2. **Substrate & Engine Value Types**: Foundational primitives (`Severity`, `OxidizeRng`, `QmcError`, `UnitInterval`, `PositiveFloat`, `NonNegativeFloat`, `StepSize`, `GridIndex`, `Dimension`, `FitModel`, `CurveFit`, `LocalExtremum`, `MathError`, `FitError`) in [`crates/00_foundation/math_diagnostics`](../../crates/00_foundation/math_diagnostics/Cargo.toml), [`crates/00_foundation/math_rng`](../../crates/00_foundation/math_rng/Cargo.toml), and [`crates/math_commons`](../../crates/math_commons/Cargo.toml) and `#![no_std]` solver value/report types in [`crates/02_engines/engine_linalg`](../../crates/02_engines/engine_linalg/Cargo.toml), [`crates/engine_diffeq`](../../crates/engine_diffeq/Cargo.toml), and [`crates/engine_pde`](../../crates/engine_pde/Cargo.toml) needed unified optional `serde` support.
3. **Plot Outputs & Facade Feature Forwarding**: [`egui_plot`](../../egui_plot/Cargo.toml) derived `serde` on `FitType` and `SharedPoints` but omitted `serde` on `FitResult`, `CriticalPointKind`, and `CriticalPoint`, while [`math_explorer/Cargo.toml`](../../math_explorer/Cargo.toml) lacked an opt-in `serde` feature forwarding serialization to foundational and external math re-exports.

## Decision
1. **Configure `#![no_std]` Workspace `serde` Dependency**: Set `default-features = false` on `serde` in [`Cargo.toml`](../../Cargo.toml) and explicitly enable `serde/std` in `std`-assuming crates (`verified_engine`, `oxidize_core`, `pure_math`, `domain_physics`, `unified_verification`, `markdown_tests`, and `math_explorer_gui`).
2. **Expose Opt-In `#![no_std]` `serde` Features on Substrate and Engine Crates**:
   - Define optional `serde` features (disabled by default) in [`crates/00_foundation/math_diagnostics/Cargo.toml`](../../crates/00_foundation/math_diagnostics/Cargo.toml), [`crates/00_foundation/math_rng/Cargo.toml`](../../crates/00_foundation/math_rng/Cargo.toml), [`crates/math_commons/Cargo.toml`](../../crates/math_commons/Cargo.toml), [`crates/02_engines/engine_linalg/Cargo.toml`](../../crates/02_engines/engine_linalg/Cargo.toml), [`crates/engine_diffeq/Cargo.toml`](../../crates/engine_diffeq/Cargo.toml), and [`crates/engine_pde/Cargo.toml`](../../crates/engine_pde/Cargo.toml), and keep default builds of `math_diagnostics`, `math_rng`, `engine_linalg`, `engine_diffeq`, and `engine_pde` free of both `std` and `serde`.
   - Implement `TryFrom<f64>` delegating to `Self::new` in `define_bounded_float!` and `define_strictly_bounded_float!` in [`crates/math_commons/src/primitives.rs`](../../crates/math_commons/src/primitives.rs) and wire `#[serde(try_from = "f64", into = "f64")]` so deserializing `UnitInterval`, `PositiveFloat`, and `NonNegativeFloat` rejects `NaN`, `Infinity`, and out-of-domain scalars.
   - Enforce structural invariants during deserialization of `CurveFit` (`coeff_len <= 5`), `CompiledExpr` (`axis_count <= var_names.len()`, valid `LoadVar` slots, and balanced postfix stack depth), `FitError` (zero-allocation `DeserializeOwned` over static domain reasons), `StreamingQr` (`1 <= ncols <= MAX_P` and finite triangular state), and `BaoabLangevinSolver` (positive `mass` and `dt`, non-negative `friction` and `temperature`, and recomputed thermostat constants).
   - Omit `serde` on transient borrowed and scratch views (`SolverWorkspace`, `DenseView`, `CsrMatrixView`, `OwnedWorkspace`, and `PdeOwnedWorkspace`), keep deleted `oxidize_core` lifecycle traits from [ADR 0036](0036-delete-simulation-model-traits-and-physics-adapters.md) absent, and leave existing `math_explorer_gui` shadow preset structs governed by [ADR 0022](0022-unify-preset-state-serialization.md) unchanged.
3. **Add `egui_plot` Output Serialization and `math_explorer/serde` Facade Forwarding**:
   - Enable `math_commons/serde` from `egui_plot/serde` in [`egui_plot/Cargo.toml`](../../egui_plot/Cargo.toml) and derive optional `serde` on `FitResult` (skipping `custom_evaluator` via `#[serde(skip)]`), `CriticalPointKind`, and `CriticalPoint`.
   - Expose an optional `serde` feature in [`math_explorer/Cargo.toml`](../../math_explorer/Cargo.toml) (and [`crates/pure_math/Cargo.toml`](../../crates/pure_math/Cargo.toml)) forwarding serialization to `math_commons`, `#![no_std]` engines, `dashu`, `nalgebra`, `num-complex`, `petgraph`, and `rand`.

## Consequences
- **Positive**:
  - `#![no_std]` embedded callers, plotting consumers, and `math_explorer` integrators gain opt-in serialization across value, config, and error types with domain validation on load and zero heap allocations in solver stepping loops.
  - Default engine builds compile without `std` or `serde`, existing GUI presets remain byte-compatible, and compressed WebAssembly bundles remain well within the 4 MB budget.
- **Negative**:
  - Deserializing a `FitResult` whose `fit_type` is `FitType::Custom` restores parameters, formula text, and residuals with `custom_evaluator: None`; callers must re-bind their runtime `CustomFitEvaluator` callback if post-load custom evaluation is needed.
