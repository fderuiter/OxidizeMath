# ADR 0043: Gate `serde` Behind Optional Cargo Features, Validated Bounded Deserialization, and GUI Shadow-Type Consolidation

## Status
Accepted (extends [ADR 0004](0004-unified-verification-dependency-audit.md) and [ADR 0034](0034-curate-math-explorer-facade-exports-and-doctests.md))

## Context
[ADR 0034](0034-curate-math-explorer-facade-exports-and-doctests.md) pared down [`math_explorer/Cargo.toml`](../../math_explorer/Cargo.toml) under `default = []`, yet three serialization gaps remained across the mathematical workspace, plotting library, and GUI application:
1. **Unconditional `serde` Macro Footprint in Math & Support Crates**: `pure_math`, `domain_physics`, `oxidize_core`, `verified_engine`, `diagnostics`, and `scientific_metadata` pulled `serde` (with `derive`) unconditionally, while `math_commons`, `domain_ai`, `domain_applied`, `domain_biology`, `domain_climate`, and `domain_epidemiology` lacked `serde` feature flags altogether. Downstream consumers embedding `math_explorer` without serialization still paid procedural-macro compile cost when enabling domain features, while consumers needing JSON/TOML persistence could not serialize most domain models, errors, or bounded primitives.
2. **Unvalidated Deserialization Risk on Bounded Primitives**: Core and domain invariant types (`UnitInterval`, `PositiveFloat`, `NonNegativeFloat`, `DepthOfDischarge`, `Capacity`, `Cycles`, and domain-constrained models) enforce finite range invariants in fallible `new(...)` constructors, whereas derived `Deserialize` implementations would bypass those invariants and admit `NaN`, `±infinity`, or out-of-bounds payloads.
3. **Duplicated Shadow Types & Manual Validation Boilerplate in `math_explorer_gui` and `egui_plot`**: Because canonical math types and `egui_plot` analysis types (`FitType`, `FitResult`, `CriticalPointKind`, `CriticalPoint`) lacked `Serialize`/`Deserialize` support, [`math_explorer_gui`](../../math_explorer_gui/Cargo.toml) maintained parallel shadow enums (`CrystalSystemEnum`, `SurfaceType`, `CurvatureType`), mirrored parameter fields (`ExponentialKernel`), and repeated manual `is_finite()` / range validation boilerplate across tool state structs.

## Decision
1. **Optional `serde` Feature Flag Across All Math & Support Crates**:
   - Gate `serde` behind `default = []` and an explicit `serde` Cargo feature across all `8` mathematical crates (`math_commons`, `pure_math`, `domain_ai`, `domain_applied`, `domain_biology`, `domain_climate`, `domain_epidemiology`, `domain_physics`) and support crates (`oxidize_core`, `verified_engine`, `diagnostics`, `scientific_metadata`).
   - Forward optional upstream serialization features (`nalgebra/serde-serialize`, `dashu/serde`, `num-complex/serde`, `petgraph/serde-1`) from each crate's `serde` feature and expose a top-level `serde` feature on [`math_explorer/Cargo.toml`](../../math_explorer/Cargo.toml) using conditional `?` syntax (`pure_math?/serde`, `domain_*?/serde`, `oxidize_core?/serde`, `nalgebra?/serde-serialize`, `num-complex?/serde`, `petgraph?/serde-1`) so enabling `serde` never implicitly activates unrequested domain crates.
   - Gate `Serialize`/`Deserialize` derives on `Point3D`, `Mesh`, `NeumannBoundary`, `IterationPattern`, and `TraceabilityReport` in [`crates/oxidize_core/src/lib.rs`](../../crates/oxidize_core/src/lib.rs) under `#[cfg_attr(feature = "serde", ...)]`.
2. **Invariant-Preserving Serialization Across Bounded Primitives, Domain Models, and `egui_plot`**:
   - Implement transparent `Serialize` and validated `Deserialize` (routing through `Self::new(...)` and rejecting `NaN`, `±infinity`, and out-of-range values via `serde::de::Error::custom`) on bounded primitives in [`crates/math_commons/src/primitives.rs`](../../crates/math_commons/src/primitives.rs), battery degradation types in [`crates/domain_applied/src/applied/battery_degradation/types.rs`](../../crates/domain_applied/src/applied/battery_degradation/types.rs), and invariant-bearing domain newtypes and models across `pure_math` and `domain_*`.
   - Gate `#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]` across public value, configuration, state, output, error, and enum types—including new canonical domain enums `BravaisLattice` in [`crates/domain_physics/src/physics/solid_state/lattice.rs`](../../crates/domain_physics/src/physics/solid_state/lattice.rs) and `ParametricSurfaceKind` (covering `Sphere`, `Torus`, `KleinBottle`, `CustomHeightfield`, and `CustomParametric` alongside `uv_domain()`) / `CurvatureKind` in [`crates/pure_math/src/pure_math/differential_geometry/surface.rs`](../../crates/pure_math/src/pure_math/differential_geometry/surface.rs)—as well as `FitType`, `FitResult`, `CriticalPointKind`, and `CriticalPoint` in [`egui_plot/Cargo.toml`](../../egui_plot/Cargo.toml), while leaving trait-object, borrowed, and runtime-FFT/RNG solvers unserialized.
3. **GUI Shadow-Type Consolidation & Continuous Feature-Matrix Verification**:
   - Enable `serde` on `math_explorer`, `egui_plot`, `oxidize_core`, and upstream math crates in [`math_explorer_gui/Cargo.toml`](../../math_explorer_gui/Cargo.toml), replacing shadow enums (`CrystalSystemEnum`, `SurfaceType`, `CurvatureType`), mirrored `ExponentialKernel` fields, and manual finiteness/bound boilerplate with canonical `BravaisLattice`, `ParametricSurfaceKind`, `CurvatureKind`, `ExponentialKernel`, `UnitInterval`, `PositiveFloat`, `NonNegativeFloat`, `DepthOfDischarge`, `Cycles`, and `Odds` while preserving exact JSON preset/session field names and `#[serde(deny_unknown_fields)]`.
   - Extend `test-features` in [`apps/xtask/src/features.rs`](../../apps/xtask/src/features.rs) to assert via `cargo tree -e normal` that `serde` and `serde_derive` are completely absent from normal dependencies whenever `serde` is disabled, and to run `cargo test -p math_explorer` across `core-only` and every individual domain feature both without and with `serde`.

## Consequences
- **Positive**: Compiling `math_explorer` without `serde` (`--no-default-features` or any combination of domain features) pulls zero `serde` or `serde_derive` normal dependencies, keeping non-serializing builds completely free of derive-macro overhead.
- **Positive**: Deserializing untrusted JSON/TOML into bounded mathematical primitives and domain configurations automatically enforces finiteness and domain bounds at the deserialization boundary, eliminating duplicate GUI validation boilerplate and shadow enums without breaking saved preset schemas.
- **Neutral**: Workspace consumer binaries (`math_explorer_gui`, `unified_verification`, and `markdown_tests`) explicitly opt into `serde` features in their manifests where persistence or full-feature doctest parity is required.
