# ADR 0046: Unify `verify-suite` onto `AstCache`, Item-Scoped Opt-Outs, and Read-Only `--check` Mode

## Status
Accepted (extends [ADR 0011](0011-ast-citation-binding-and-cli-check-enforcement.md), [ADR 0018](0018-ci-coverage-gate-hardening.md), [ADR 0034](0034-scoped-pre-commit-and-single-parse-ast-verification.md), [ADR 0040](0040-ast-verification-spans-optout-scoping-and-api-normalization.md), and [ADR 0044](0044-unify-build-time-traceability-engine.md))

## Context
1. **Regex Drift & Duplicate Parsing in `verify-suite`**: `crates/unified_verification/src/report.rs` relied on line/regex heuristics (`fn_re`, `assert_re`, `opt_out_re`, `legacy_re`, and `content.contains("theory_verification!")`) instead of `oxidize_core::traceability::AstCache` and `oxidize_core::ast_visitor::AstVisitor`. Comments and string literals such as `// theory_verification!` spoofed crate verification checks, inner `#![cfg_attr(any(), verified(opt_out = "..."))]` attributes went undetected by outer-only regexes, and `report.rs` / `wasm_coverage.rs` re-read and re-parsed Rust files independently of `AstCache`.
2. **Whole-File `opt_out` Contamination & Synthetic Macro Floors**: `AstVisitor` flipped a file-wide `opted_out = true` boolean upon encountering any item-level `#[verified(opt_out = "...")]`, dropping sibling `#[verified]` function/assertion counts and masking remaining unverified functions in that file. Separately, `AstVisitor::visit_item_macro` applied `.max(3)` to `theory_verification!` and `stochastic_signature_verification!`, awarding synthetic assertions to empty `test = {}` blocks, and pooled `#[test]` assertions together with production assertions.
3. **Advisory Debt Reporting, Dirty CI Worktrees, & Pre-Commit Traceability Gaps**: `report.rs` printed integrity debt items without failing `passed` or exiting non-zero on unauthorized debt, `verify-suite` mutated `Verification_Certificate.json` and `README.md` unconditionally during CI `build-and-test`, and `batch-staged` skipped `run_traceability_with_cache` even when `traceability.toml`, `papers/`, or domain Rust files were staged.

## Decision
1. **Single-Pass `AstCache` + `AstVisitor` Unification**: Replace regex/substring source scanning in `crates/unified_verification/src/report.rs` and `wasm_coverage.rs` with `AstCache` (using lexical `.` / `..` path normalization) and `oxidize_core::ast_visitor::AstVisitor` so every unique workspace `.rs` file is parsed by `syn::parse_file` at most once per `verify-suite` or `batch-static` run, and remove all `// theory_verification!` spoofing comments.
2. **Structured `cfg_attr` Parsing, Item-Scoped `opt_out`, & Exact Macro Assertions**: Update `AstVisitor` (`crates/oxidize_core/src/ast_visitor.rs` and `src/ast_visitor/attrs.rs`) to parse outer `#[...]`, inner `#![...]`, and nested `cfg_attr(...)` attributes via `syn::Meta`, scope item opt-outs strictly to the annotated item (`opted_out_funcs`) so `traceability/analysis.rs` preserves sibling `#[verified]` counts while flagging unopted unverified files, remove the `.max(3)` macro assertion floor, and track production vs. test function/assertion counts separately.
3. **Fail-Closed Whitelist Debt & Ratcheted Production Density Floors**: Introduce `[verify_suite]` in `verification_whitelist.toml` (`crates/unified_verification/src/whitelist.rs`) specifying `min_verified_assertion_density` (`0.40`), ratcheted `min_total_production_density` and `min_verified_production_density` floors, `coverage_tolerance_pct` (`1.5`), authorized non-domain `unverified_modules`, and scoped `[[verify_suite.opt_outs]]` rules. Any unwhitelisted module, unauthorized `opt_out`, `*_legacy` function, file-length violation, or entropy violation sets `passed = false` and exits `1`.
4. **Read-Only `--check` Default, Static Certificate Parity, & Scoped Staged Traceability**: Default `verify-suite` to read-only `--check` (requiring explicit `--write` to update `Verification_Certificate.json` and `README.md`), add `check-certificate` to `batch-static` and CI `pre-flight` comparing deterministic AST fields within `1e-6` while checking `native_execution_coverage_pct` within `coverage_tolerance_pct` during `verify-suite --check` in CI `build-and-test`, and run `run_traceability_with_cache(false, cache)` inside `batch-staged` whenever staged paths touch `traceability.toml`, `papers/`, or traceability-monitored crates.

## Consequences
- **Positive**: Eliminates comment/string spoofing and duplicate `syn::parse_file` work across `verify-suite`, `batch-static`, and `check-certificate` while keeping `Verification_Certificate.json` backward-compatible with web staging and `TraceabilityTab`.
- **Positive**: Prevents CI runs from dirtying tracked files, catches stale certificates in fast `pre-flight` static checks before `cargo-llvm-cov`, and catches broken `[cite:...]` or unverified domain functions at pre-commit time without slowing unrelated docs/tooling commits.
- **Neutral**: Refreshing `Verification_Certificate.json` and `README.md` locally after intentional metric shifts now uses `cargo run -p unified_verification -- verify-suite --write`, and `crates/unified_verification/api_baseline.json` records the expanded `AstVisitor` fields alongside `Sample2D::advance_slice_plateau` / `PointSeries::advance_plateau` (preserving sub-5ms 8-wide branchless plateau scanning under `cargo-llvm-cov` coverage instrumentation).
