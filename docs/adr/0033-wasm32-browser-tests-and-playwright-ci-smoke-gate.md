# ADR 0033: Browser-Executed `wasm32` Unit Tests, Headless Chromium CSP Smoke Gate, and AST-Verified WASM Path Coverage

## Status
Accepted (extends [ADR 0022](0022-wasm-clippy-guardrails.md) and [ADR 0032](0032-precomputed-traceability-manifest-and-wasm-vfs-subpaths.md))

## Context
Three verification gaps left browser-only WebAssembly runtime paths and the static GitHub Pages bundle vulnerable to silent regressions:
1. **Compile-Only `wasm32` CI Checks**: In [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml), the `Web/WASM` leg ran `cargo check`, `cargo clippy`, and `trunk build --release`, then uploaded `wasm_web_dist` for `deploy-pages` without ever executing `wasm32-unknown-unknown` unit tests or booting [`math_explorer_gui`](../../math_explorer_gui/src/main.rs) in a headless browser under production `Content-Security-Policy` headers.
2. **Untested Browser Storage, DOM, and Fault-Recovery Boundaries**: WebAssembly virtual filesystem operations in [`crates/oxidize_core/src/vfs.rs`](../../crates/oxidize_core/src/vfs.rs), browser I/O and URL/theme/live-region bindings in [`math_explorer_gui/src/web_io.rs`](../../math_explorer_gui/src/web_io.rs), [`math_explorer_gui/src/url_state/browser.rs`](../../math_explorer_gui/src/url_state/browser.rs), [`math_explorer_gui/src/app/theme.rs`](../../math_explorer_gui/src/app/theme.rs), and [`math_explorer_gui/src/accessibility.rs`](../../math_explorer_gui/src/accessibility.rs), and pre-boot/WebGL recovery paths in [`math_explorer_gui/src/main.rs`](../../math_explorer_gui/src/main.rs), [`math_explorer_gui/reload.js`](../../math_explorer_gui/reload.js), and [`math_explorer_gui/bootstrap.js`](../../math_explorer_gui/bootstrap.js) were only validated via native string assertions rather than real Chromium execution.
3. **Comment-Spoofed `wasm_path_coverage_pct`**: [`crates/unified_verification/src/report.rs`](../../crates/unified_verification/src/report.rs) marked any `#[cfg(target_arch = "wasm32")]` item as covered whenever the file contained the substring `theory_verification!` or `stochastic_signature_verification!`—including plain `// theory_verification!` comments—reporting `100.0%` WASM path coverage with zero executed browser tests.

## Decision
1. **Executable Browser `wasm32` Unit Tests via Playwright Chromium**:
   - Add `wasm-bindgen-test` under `[target.'cfg(target_arch = "wasm32")'.dev-dependencies]` in [`crates/oxidize_core/Cargo.toml`](../../crates/oxidize_core/Cargo.toml) and [`math_explorer_gui/Cargo.toml`](../../math_explorer_gui/Cargo.toml), configured with [`scripts/wasm_test_runner.py`](../../scripts/wasm_test_runner.py) in [`.cargo/config.toml`](../../.cargo/config.toml).
   - Execute real `#[wasm_bindgen_test]` suites in headless Chromium under production CSP headers covering `WasmVfs` (`list_dir`, `fetch` `200`/`404`, `Blob` downloads), `TraceabilityEngine::verify_module_registered`, `PlatformInstant`, browser download channels, `History.replaceState` URL state, `matchMedia` and document theme synchronization, WAI-ARIA twin-slot live regions, and pre-boot DOM/WebGL failure helpers.
2. **Localhost CSP Smoke & Fault-Injection Gate (`xtask test-wasm`)**:
   - Implement [`scripts/playwright_smoke.py`](../../scripts/playwright_smoke.py) to serve `math_explorer_gui/dist` on `localhost` with the exact `Content-Security-Policy` header from [`math_explorer_gui/Trunk.toml`](../../math_explorer_gui/Trunk.toml) (verifying byte-for-byte parity with `dist/index.html`) without inline script injection or `eval` polling.
   - Verify HTTP `200` startup asset responses, zero console/page errors, zero CSP violations, `#loading_indicator` removal, interactive WebGL canvas rendering, and focus on `#the_canvas_id`, plus fault-injected `network` (missing `.wasm`, broken loader/bootstrap scripts), `compile` (corrupted `.wasm`), `timeout` (stalled `.wasm` transfer), and `webgl` (disabled WebGL context) error boundaries and focus transfer to `#webgl_reload_button`, along with negative regression checks.
   - Expose `cargo run -p xtask -- test-wasm` in [`apps/xtask/src/gates.rs`](../../apps/xtask/src/gates.rs) and run `cargo run -p xtask -- test-wasm --skip-build` in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) after `trunk build --release` and before `Upload Web Dist Artifact`.
3. **AST-Verified `wasm_path_coverage_pct`**:
   - Replace substring/comment matching in [`crates/unified_verification/src/report.rs`](../../crates/unified_verification/src/report.rs) with [`crates/unified_verification/src/wasm_coverage.rs`](../../crates/unified_verification/src/wasm_coverage.rs), using `syn` AST traversal to count `#[cfg(target_arch = "wasm32")]` production paths as covered strictly when backed by real `#[wasm_bindgen_test]` test functions.

## Consequences
- **Positive**: Regressions in WebAssembly loading, strict CSP compliance, WebGL canvas initialization, browser storage/DOM bindings, or accessible startup error recovery deterministically fail `xtask test-wasm` locally and block `wasm_web_dist` upload and `deploy-pages` in CI.
- **Positive**: `Verification_Certificate.json` reports genuine AST-verified `wasm_path_coverage_pct` immune to `// theory_verification!` comment spoofing.
- **Neutral**: Production static bundle dependencies and compressed `.wasm.br` / `.wasm.gz` size remain unchanged within the 3 MB budget because `wasm-bindgen-test` is scoped exclusively to `wasm32` `dev-dependencies`.
