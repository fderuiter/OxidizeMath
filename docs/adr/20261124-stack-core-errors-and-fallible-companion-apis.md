# ADR 20261124: Stack-Allocated Core Errors, Fallible Companion APIs, and AST Error Contract Verification

## Status
Accepted (extends [ADR 20261124](20261124-complete-checked-apis-and-typed-domain-errors.md), [ADR 20261123](20261123-nostd-diffeq-and-pde-engines.md), [ADR 20261124](20261124-no-std-math-diagnostics-and-causal-error-wiring.md), and [ADR 20261124](20261124-optional-no-std-serde-substrate-and-facade.md))

## Context
Following the typed domain `Result` migrations and initial checked constructors in [ADR 20261124](20261124-complete-checked-apis-and-typed-domain-errors.md), Tier-0 [`math_diagnostics`](../../crates/00_foundation/math_diagnostics/src/lib.rs), Tier-0 [`math_rng`](../../crates/00_foundation/math_rng/src/lib.rs), and `#![no_std]` numerical engines (`engine_diffeq` and `engine_pde`), four structural gaps remained across Tier 0–3 crates:
1. **Heap-Backed `MathError` Payloads and Unconditional `alloc` Coupling**: [`crates/math_commons/src/error.rs`](../../crates/02_engines/math_commons/src/error.rs) stored `alloc::string::String` payloads inside `MathError::NumericalError` and `MathError::ConversionError`, preventing `Copy + Eq` stack semantics and pulling `alloc` into bare `--no-default-features` builds (including [`Interval`](../../crates/02_engines/math_commons/src/primitives/interval.rs)). Likewise, [`crates/diagnostics`](../../crates/01_core/diagnostics/src/lib.rs) panicked on empty source labels without a typed `DiagnosticError` or fallible `try_emit_diagnostic_with_source` companion, and [`crates/00_foundation/math_rng`](../../crates/00_foundation/math_rng/src/scalar.rs) lacked a typed `RngError` and `try_sample_bounded_*` companions for zero upper bounds.
2. **Missing `#![no_std]` Engine Error Enums (`DiffeqError`, `PdeError`) and Stepping Companions**: While `BaoabLangevinSolver::try_new` and `SemiImplicitFourierStepper::try_new_{1d,2d}` validated scalar constructor bounds, `engine_diffeq` and `engine_pde` still panicked via `assert!` during SDE/SPDE stepping, FFT radix-2 kernel execution, stencil point evaluation, and `OwnedWorkspace` allocation without dedicated `#![no_std]` `Copy + Eq` engine error enums.
3. **Remaining Uncompanioned Panicking Public Library Functions**: Remaining public constructors and numerical routines across `pure_math`, `domain_*`, `oxidize_core`, and `scientific_metadata` crates asserted or unwrapped preconditions without exposing fallible `try_*` / `checked_*` companions, and root [`Cargo.toml`](../../Cargo.toml) did not deny `clippy::result_unit_err`.
4. **No Automated AST Gate Against Regression**: `unified_verification` lacked an in-process AST pass in `batch-ast` to reject newly added untyped `Result<_, String | &str | ()>` public library signatures or uncompanioned panicking public library functions.

## Decision
1. **Stack-Allocated `Copy + Eq` `#![no_std]` Core and Engine Errors**:
   - Reuse Tier-0 [`math_diagnostics::Diagnostic`](../../crates/00_foundation/math_diagnostics/src/lib.rs) across all core and engine errors; add `Copy + Eq` [`DiagnosticError`](../../crates/01_core/diagnostics/src/lib.rs) (`EmptySource`) and `DiagnosticBus::try_emit_diagnostic_with_source`, and add `Copy + Eq` [`RngError`](../../crates/00_foundation/math_rng/src/scalar.rs) (`ZeroUpperBound`) with `try_sample_bounded_u64` / `try_sample_bounded_usize`.
   - Gate `alloc` explicitly in [`crates/math_commons/Cargo.toml`](../../crates/02_engines/math_commons/Cargo.toml) (`default = ["std"]`, `alloc = ["math_rng/alloc"]`, `std = ["alloc", ...]`, `serde = ["alloc", ...]`) and convert [`MathError`](../../crates/02_engines/math_commons/src/error.rs) to a stack-only `Copy + Eq` `#![no_std]` enum implementing `core::fmt::Display`, `core::error::Error`, and `math_diagnostics::Diagnostic` without `alloc` or `std` (replacing heap `String` reasons on `NumericalError` and `ConversionError` with `&'static str`, and isolating zero-allocation `serde::Deserialize` lookup in [`crates/math_commons/src/error/math_serde.rs`](../../crates/02_engines/math_commons/src/error/math_serde.rs)).
   - Define `Copy + Eq` `#![no_std]` [`DiffeqError`](../../crates/02_engines/engine_diffeq/src/error.rs) and [`PdeError`](../../crates/02_engines/engine_pde/src/error.rs) enums (with optional `#![no_std]` `serde` support) and expose `try_*` step, kernel, and workspace companions across `engine_diffeq` and `engine_pde` while preserving existing `BaoabLangevinSolver::try_new` and `SemiImplicitFourierStepper::try_new_{1d,2d}` signatures.
2. **Fallible Companions and Umbrella Wiring**:
   - Deny `result_unit_err = "deny"` under `[workspace.lints.clippy]` in root [`Cargo.toml`](../../Cargo.toml).
   - Add `CitationRegistry::{try_get, try_register}` returning `CitationRegistryError`, upgrade `ReactionDiffusionError`, `QuantumError` (extended with `DimensionMismatch`), and `VoxelGridError` to `Copy + Eq`, scope crate-umbrella `From<E>` verification in [`facade_umbrella.rs`](../../apps/unified_verification/src/api_drift/facade_umbrella.rs) to each crate's actual Tier-2 engine dependencies, and wire `DiagnosticError`, `DiffeqError`, and `PdeError` into [`math_explorer/src/error.rs`](../../crates/04_bindings/oxidizemath/src/error.rs).
   - Add `try_*` / `checked_*` companion functions across `pure_math` and `domain_*` crates while retaining existing convenience wrappers (`new`, operator traits, and solver trait implementations) that delegate to their fallible counterparts.
3. **Enforce Error Contracts in `unified_verification` `batch-ast`**:
   - Add [`crates/unified_verification/src/error_contracts.rs`](../../apps/unified_verification/src/error_contracts.rs) into `batch-ast` (and therefore `batch-static`) to audit public library items from the shared `AstCache`, rejecting untyped `Result` error types (`()`, `String`, `&str`, `&'static str`) and uncompanioned panicking public library functions outside trait-contract allowlists (`Index`, `IndexMut`, `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg`, etc.) and internal `publish = false` verification harnesses.

## Consequences
- **Positive**: `math_rng`, `math_commons`, `engine_diffeq`, and `engine_pde` compile and pass unit tests under `--no-default-features` without `alloc` or `std`, with zero heap allocations on any core or engine error path and full optional `#![no_std]` `serde` compatibility.
- **Positive**: `batch-ast` / `batch-static` deterministically prevent regressions in typed error contracts and fallible companion coverage across all library and facade crates.
- **Neutral**: Convenience panicking wrappers and trait implementations remain available for ergonomic trusted-input callers while delegating precondition checks to `try_*` / `checked_*` companions.
